## 踩坑记录

### 1. 驱动签名检查

**问题**: pnputil 拒绝安装未签名 INF
```
第三方 INF 不包含数字签名信息。
```

**原因**: Windows 11 Build 26200 强制要求驱动目录文件签名。即使 `testsigning on` + `nointegritychecks on` 也无法跳过。

**解决**: 
- 创建代码签名证书（导出私钥为 PFX）
- 使用 makecat 生成 .cat 目录文件
- signtool 签名 .cat
- INF 添加 `CatalogFile=SBMS.cat`

### 2. INF 文件不能直接签名

**问题**: signtool 报错
```
This file format cannot be signed because it is not recognized.
```

**原因**: INF 是文本文件，非 PE 格式，Authenticode 不支持直接签名。

**解决方案**: 通过目录文件 (.cat) 间接签名。INF 引用 .cat，对 .cat 签名即等同于对 INF 签名。

### 3. 证书私钥不可导出

**问题**: signtool 找不到证书
```
No certificates were found that met all the given criteria.
```

**原因**: `New-SelfSignedCertificate` 默认不标记私钥为可导出，导致 Export-PfxCertificate 失败。

**解决**: 创建证书时需加参数：
```powershell
New-SelfSignedCertificate -KeyExportPolicy Exportable
```

### 4. Enum 注册表写入权限

**问题**: 无法创建根设备节点
```
reg add "HKLM\SYSTEM\CurrentControlSet\Enum\Root\IddSampleDriver\0000"
拒绝访问。
```

**原因**: `Enum` 键受 TrustedInstaller 保护，管理员也无法直接写入。

**解决**: 通过 WMI/CIM 以 SYSTEM 身份执行：
```powershell
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{
    CommandLine = "cmd /c reg add ..."
}
```

### 5. PnP 重新枚举

**问题**: 注册表写入后设备未出现
**原因**: `pnputil /scan-devices` 需要完整 SYSTEM 权限，或通过 cfgmgr32 API 触发。
**解决**: 重启后 PnP 自动枚举 `Enum\Root` 下的设备。

### 6. 驱动依赖 IndirectKmd

**问题**: 设备可能出现但无功能
**原因**: IddSampleDriver（UMDF）需要一个内核模式的上层过滤器 `IndirectKmd`。
**解决**: 在设备参数中添加：
```
UpperFilters = IndirectKmd
```
