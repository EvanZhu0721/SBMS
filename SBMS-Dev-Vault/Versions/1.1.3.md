# 1.1.3

## Product changes

- Replaces the IDD-to-CPU shared-frame path and GDI scaling with a GPU-only
  Desktop Duplication, D3D11 shader, and flip-model presentation path.
- Keeps the IDD responsible only for its validated session mode and timely
  IddCx swapchain completion. WUDFHost no longer stages, maps, or copies full
  desktop frames.
- Removes nonce-derived shared frame mappings and events. The protected fixed
  session gate remains the single-session mode and ownership boundary.
- Handles Desktop Duplication pointer position, visibility, hotspot, shape,
  and whether Windows already included the pointer in the duplicated image.
  No fixed arrow is drawn.

## Scaling and text quality

- Bypasses filtering for a 1:1 mapping.
- For a 1x..=2x reduction on each axis, integrates exact source-pixel area with
  four bilinear texture fetches.
- Uses two additional horizontal samples for a neutral-content-gated,
  luminance-preserving chroma low-pass. This reduces colored ClearType fringes
  after non-integer scaling while avoiding blanket desaturation of colored UI.
- Falls back to bilinear sampling outside the exact-area range.

The chroma pass is an image heuristic, not font recognition. It does not
reconstruct font outlines, provide gamma-linear resampling, HDR, or color
management.

## Verified locally

- The signed 1.1.3 installer and IDD installed successfully.
- All 34 Rust tests pass.
- Clippy reports no warnings.
- Driver WDK/API validation passes.
- A 4640x2610@240 virtual source mapped to a 2560x1440 target and reached
  first-frame confirmation, then stopped normally.
- During a 12-second dynamic-cursor workload, presentation held 239-240 fps.
  WUDFHost used 0% CPU and exposed no GPU engine above 0.01%. The `sbms`
  renderer used 0% CPU, with 3D-engine load averaging 3.36% and peaking at
  3.44%.

This is one-machine cursor-driven composition stress evidence. It is not a
promise that every workload, display stack, or GPU sustains 240 fps.

## Boundary

Native Windows clone-mode semantics, HDR and color management, low-latency
game-streaming guarantees, active-session mode changes, multiple simultaneous
virtual displays, and general runtime topology recovery remain out of scope.
