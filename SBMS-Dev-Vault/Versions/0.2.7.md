# 0.2.7

Status: implemented; window migration verified locally with a signed test
driver.

## Product capability

- One fixed 3840x2160@240 BGRA test virtual mode mapped to one explicitly
  selected active physical display.
- Stable target identity remains DisplayConfig `monitorDevicePath`.
- Start migrates eligible visible standard top-level windows from the target
  physical display to the virtual source before reporting the mapping as
  running. A 250 ms scanner continues handling newly opened windows and tracked
  windows moved back to the target.
- Stop restores those windows before mirror teardown. After the virtual source
  disappears from the topology, SBMS reconciles placement once more against the
  final physical-only layout.
- Normal and maximized windows have completed local round-trip tests across
  displays with different DPI settings; the test also covered a window opened
  after the session started.
- Start still requires a valid first frame, and stop remains bounded.

## Window migration boundary

The migration layer records window identity, placement, outer rectangle, state,
and monitor before moving a window. Restoration validates the saved window
identity to avoid applying old state to a reused handle.

This is not a general window manager and cannot promise lossless restoration
for every process. Minimized windows are deliberately left untouched because
their workspace-coordinate placement is not safe to rewrite generically across
DPI and taskbar layouts. UIPI and higher-integrity windows may reject control;
hung applications may not respond; self-positioning applications may overwrite
the requested placement; and windows closed or recreated during the session no
longer have the same restorable identity.

## Display and transport

The IDD now advertises a fixed 3840x2160@240 mode, and the frame channel,
protected gate, mapping, and event names moved to protocol v3.

The mode is a capability and stress-test target, not a measured 240 fps
guarantee. Each 4K BGRA frame is about 31.6 MiB. The current path still performs
D3D11 CPU staging readback, a full driver-to-shared-memory copy, and GDI output,
so it is not expected to sustain 240 complete 4K frames per second. A slow
consumer drops frames instead of blocking the IddCx swapchain.

## Explicit exclusions

No GUI, configuration persistence, background service, production installer,
automatic target selection, multi-mapping, dynamic display modes, general
runtime topology recovery, cursor composition, input forwarding, HDR, color
management, native clone-mode semantics, or all-GPU transport.

## Use

From an elevated PowerShell terminal:

```powershell
cargo build --release

.\build-driver.ps1 `
  -SigningCertificateThumbprint <certificate-thumbprint>

pnputil /add-driver `
  .\target\driver\SBMSIndirectDisplay.inf `
  /install

.\target\release\sbms.exe list

.\target\release\sbms.exe map `
  --target '<complete physical id>'
```

Copy the complete `id=` from a `physical` line. Eligible target windows migrate
automatically. Press Enter to take the normal restoration path, or add
`--hold-ms 5000` for a bounded run. Forcibly terminating the process bypasses
user-mode restoration. `sbms create --hold-ms 5000` tests only the
virtual-device lifetime and does not migrate windows or map pixels.
