# 1.1.2

## Product changes

- Connects the saved `SizingRequest` to `MappingRequest`, the v4 session gate,
  the IDD monitor/target mode, the shared BGRA frame layout, and the renderer.
- Publishes one validated mode per mapping session. The default remains
  3840x2160@240 only when no sizing request exists.
- Detects Windows restoring an older desktop source resolution for the stable
  virtual-monitor identity, enumerates the exact legal GDI mode, applies it
  temporarily, and waits for DisplayConfig convergence.
- Snapshots the physical topology before virtual-device creation. Failed-start
  cleanup and normal stop restore it after removal, preventing Windows display
  rearrangement from escaping the session.
- `sbms list` now reports both source rectangle and target-native dimensions.

## Driver fix

1.1.1 called `IddCxMonitorUpdateModes` immediately after initial monitor
arrival. UMDF Verifier correctly treated that first-arrival lifecycle timing as
a fatal DDI violation and repeatedly terminated `WUDFHost`. 1.1.2 removes the
redundant call; the normal dynamic mode callbacks are the sole mode source.

## Verified locally

- The IDD exposes exactly one 4640x2610@240 mode for the configured session.
- Active DisplayConfig reports source and target-native dimensions as
  4640x2610 with refresh 240/1.
- Mapping reaches first-frame confirmation and stops normally.
- After stop, the virtual source is absent and both physical displays retain
  their pre-removal positions, source modes, and refresh rates.
- Driver package 1.1.2 is Best Ranked / Installed; no new UMDF runtime failure
  was recorded after the lifecycle fix.

## Boundary

Mode selection is per-session at start. Active-session hot mode changes,
multiple simultaneous virtual displays, HDR, Windows output rotation, an
all-GPU renderer, and a sustained 240 fps guarantee remain out of scope.
