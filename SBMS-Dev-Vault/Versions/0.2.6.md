# 0.2.6

Status: verified locally with a signed test driver.

## Product capability

- One fixed 1920x1080@60 virtual source mapped to one explicitly selected active
  physical display.
- Stable target identity is DisplayConfig `monitorDevicePath`.
- Start reports success only after the first valid frame is drawn.
- Stop is bounded and restores the physical-only topology.
- One session at a time; a second session fails before device creation.

## Performance

The frame protocol now has two slots. The driver writes the non-published slot,
drops a frame rather than waiting for a busy reader slot, and atomically
publishes completed pixels. Rust leases that slot directly for
`StretchDIBits`; the former 7.91 MiB-per-frame Rust copy is gone.

Scaling changed from `HALFTONE` to `COLORONCOLOR`. On the same 2560x1440 target,
five-second Rust CPU time moved from a 0.2.5 range of 2625–3219 ms to a 0.2.6
range of 109–188 ms. This measurement is machine-specific. The tradeoff is less
smooth scaling on non-1920x1080 targets.

This is not zero-copy. D3D11 staging readback, one driver-to-shared-memory copy,
and GDI output remain.

## Authorization

`Global\SBMSSession-v2` is a protected file-mapping gate. Its DACL permits only
the launching user, SYSTEM, LocalService, and Administrators. It carries a
128-bit random session ID generated by Windows CNG; the actual frame mapping and
event use names derived from that ID.

An anonymous token was denied when opening the gate, frame mapping, and event,
and was denied when attempting to pre-create the gate. All failures returned
`ERROR_ACCESS_DENIED (5)`. The real LocalService UMDF host still completed the
pixel path.

This authorizes Windows identities, not individual processes. Other processes
running as an allowed identity are intentionally inside the trust boundary.

## Explicit exclusions

No GUI, persistence, auto-selection, multi-mapping, dynamic mode, rotation,
HDR, cursor or input transport, window migration, topology recovery, native
clone-mode semantics, all-GPU transport, production installer, or production
driver signature.

## Use

From an elevated PowerShell terminal:

```powershell
cargo build --release

.\build-driver.ps1 `
  -SigningCertificateThumbprint <certificate-thumbprint>

pnputil /add-driver `
  .\target\driver\SBMSIndirectDisplay.inf `
  /install

.\target\release\sbms.exe --version

.\target\release\sbms.exe list

.\target\release\sbms.exe map `
  --target '<complete physical id>'
```

Press Enter to stop, or add `--hold-ms 5000`. `sbms create --hold-ms 5000`
tests only the virtual-device lifetime and does not map pixels.
